# Forward and backward chaining

An inference engine can use rules in two directions: start from the **facts** and work forwards, or start from a **goal** and work backwards.

## Forward chaining: data-driven

Start from the facts you have and ask "**what can I conclude?**". The engine works in rounds, called the **recognise–act cycle**:

1. **Match.** Find every rule whose conditions all hold and that has not fired yet. This is the **conflict set**.
2. If the conflict set is empty, **stop** (quiescence).
3. **Select** one rule from the conflict set. How to choose is the subject of lesson 4.
4. **Act.** Fire the rule: add its conclusion to working memory, then go back to step 1.

A new conclusion can make rules match that could not match before, so knowledge flows along a chain.

In the first cycle R1 cannot fire because `wet_ground` is not known yet. Once R2 concludes `wet_ground`, R1 enters the conflict set and jumps ahead of R3 because it comes first in the file.

## Backward chaining: goal-driven

Start from a **goal (hypothesis)** and ask "**is this true?**".

```
prove(goal):
  if goal is a known fact → true
  for every rule whose THEN is goal:
      prove every condition in that rule's IF   ← recursive call
  if no way succeeds → cannot be proven
```

Each condition becomes a **subgoal** to prove, and the result is an **AND/OR tree**:

- **OR**: a goal can be true in several ways (several rules conclude it).
- **AND**: a rule applies only if *all* its conditions hold.

<PlaygroundLink example="car" />

In InferLab, a subgoal supported by neither a fact nor a rule is **unprovable** (the closed-world assumption). Real systems like MYCIN **ask the user** at that point instead, which is where the WHY question comes from: "why are you asking me this?"

## Which to use

| | Forward chaining | Backward chaining |
|---|---|---|
| Starts from | Facts | A goal |
| Question | "What can I conclude?" | "Is this true?" |
| Good when | Data arrives first, many possible conclusions | A few hypotheses to check |
| Typical tasks | Monitoring, configuration (XCON) | Diagnosis (MYCIN) |
| Weakness | May derive things irrelevant to your question | You must know what to prove |

<Callout>
Both directions use **the same rules**. Only the *direction* the engine walks through them differs. Try switching Forward and Backward on the same example in the playground.
</Callout>
