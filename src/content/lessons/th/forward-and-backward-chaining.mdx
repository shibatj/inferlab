# Forward และ Backward Chaining

Inference engine ใช้กฎได้สองทิศทาง: เริ่มจาก **ข้อเท็จจริง** แล้วไล่ไปข้างหน้า หรือเริ่มจาก **เป้าหมาย** แล้วไล่ย้อนกลับ

## Forward chaining — ขับเคลื่อนด้วยข้อมูล (data-driven)

เริ่มจากข้อเท็จจริงที่มี แล้วถามว่า "**จากสิ่งที่รู้ สรุปอะไรได้บ้าง?**" engine ทำงานวนเป็นรอบ เรียกว่า **recognise–act cycle**:

1. **Match** — หากฎทุกข้อที่เงื่อนไขเป็นจริงทั้งหมด (และยังไม่เคย fire) → ได้ **conflict set**
2. ถ้า conflict set ว่าง → **หยุด** (quiescence)
3. **Select** — เลือกหนึ่งกฎจาก conflict set (วิธีเลือกคือเรื่องของบทที่ 4)
4. **Act** — fire กฎนั้น: เพิ่มข้อสรุปลง working memory แล้ววนกลับไปข้อ 1

ข้อสรุปใหม่อาจทำให้กฎอื่นที่เคย match ไม่ได้กลับ match ได้ — ความรู้จึง "ไหล" ต่อกันเป็นลูกโซ่

## Backward chaining — ขับเคลื่อนด้วยเป้าหมาย (goal-driven)

เริ่มจาก **เป้าหมาย (hypothesis)** แล้วถามว่า "**สิ่งนี้จริงไหม?**"

```
prove(goal):
  ถ้า goal เป็นข้อเท็จจริงที่รู้อยู่แล้ว → จริง
  สำหรับทุกกฎที่ THEN เป็น goal:
      พิสูจน์ทุกเงื่อนไขใน IF ของกฎนั้น   ← เรียก prove() ซ้ำ
  ถ้าไม่มีทางไหนสำเร็จ → พิสูจน์ไม่ได้
```

แต่ละเงื่อนไขกลายเป็น **เป้าหมายย่อย (subgoal)** ที่ต้องพิสูจน์ต่อ ผลคือ **AND/OR tree**:

- **OR** — เป้าหมายหนึ่งจริงได้หลายทาง (มีหลายกฎที่สรุปมันได้)
- **AND** — กฎหนึ่งจะใช้ได้ เงื่อนไข *ทุกข้อ* ต้องจริง

<PlaygroundLink example="car" />

ใน InferLab ถ้าเป้าหมายย่อยไม่มีทั้งข้อเท็จจริงและกฎรองรับ จะถือว่า **พิสูจน์ไม่ได้** (closed-world assumption) ระบบจริงอย่าง MYCIN จะ **ถามผู้ใช้** แทนในจุดนี้ — นั่นคือที่มาของคำถาม WHY: "ทำไมถึงถามเรื่องนี้?"

## เลือกแบบไหนดี

| | Forward chaining | Backward chaining |
|---|---|---|
| เริ่มจาก | ข้อเท็จจริง | เป้าหมาย |
| คำถาม | "สรุปอะไรได้บ้าง?" | "สิ่งนี้จริงไหม?" |
| เหมาะเมื่อ | ข้อมูลมาก่อน ข้อสรุปเป็นไปได้หลายแบบ | มีสมมติฐานจำนวนน้อยให้ตรวจ |
| งานตัวอย่าง | ตรวจจับ เฝ้าระวัง จัดสเปก (XCON) | วินิจฉัย (MYCIN) |
| จุดอ่อน | อาจสรุปสิ่งที่ไม่เกี่ยวกับคำถามเลย | ต้องรู้ก่อนว่าจะพิสูจน์อะไร |

<Callout>
ทั้งสองแบบใช้ **กฎชุดเดียวกัน** — สิ่งที่ต่างคือ *ทิศทาง* ที่ engine เดินผ่านกฎ ลองสลับปุ่ม Forward / Backward ใน Playground กับตัวอย่างเดียวกันดู
</Callout>
