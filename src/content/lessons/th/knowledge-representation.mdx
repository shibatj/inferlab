# การแทนความรู้ (Knowledge Representation)

ก่อนที่คอมพิวเตอร์จะใช้ความรู้ของผู้เชี่ยวชาญได้ เราต้องเขียนความรู้นั้นในรูปแบบที่โปรแกรม "อ่านและใช้เหตุผล" ได้ บทนี้ดูสามแบบที่เป็นแกนของ expert system ยุคคลาสสิก

## 1. Production rules

รูปแบบที่ใช้มากที่สุด — กฎ **IF เงื่อนไข THEN ข้อสรุป** มาจากงาน *production systems* ของ Newell และ Simon ที่ใช้จำลองการแก้ปัญหาของมนุษย์

```
rule Z5: IF mammal AND eats_meat THEN carnivore
```

- **ข้อดี:** อ่านง่าย ผู้เชี่ยวชาญตรวจเองได้ แต่ละกฎเป็นอิสระ เพิ่มทีละข้อได้ และ engine อธิบายเหตุผลได้ด้วยการย้อนดูกฎที่ใช้
- **ข้อเสีย:** เมื่อกฎมีหลายพันข้อ จะเริ่มมีกฎขัดกันหรือซ้ำซ้อนโดยไม่รู้ตัว และกฎไม่ได้บอก "โครงสร้าง" ของสิ่งต่าง ๆ เช่น นกทุกตัวมีปีก ต้องเขียนซ้ำทุกชนิดนก

## 2. Semantic networks

**Semantic network** แทนความรู้เป็น **กราฟ**: node คือแนวคิด (concept) และเส้นเชื่อมคือความสัมพันธ์ ความสัมพันธ์สำคัญที่สุดคือ **isA** ซึ่งทำให้เกิด **inheritance** — สิ่งที่อยู่ล่างได้คุณสมบัติจากสิ่งที่อยู่บนโดยอัตโนมัติ

ตัวอย่างด้านล่างมาจากงานของ **Collins & Quillian (1969)** ลองเลือก concept และ property แล้วดูว่าการค้นหาต้อง "ไต่" ขึ้นไปกี่ขั้น

<SemanticNetWidget />

Collins และ Quillian ทดลองให้คนตอบว่าประโยคจริงหรือเท็จ และพบว่าคนใช้เวลา **นานขึ้น** กับประโยคที่ต้องไต่ลำดับชั้นไกลขึ้น — เช่นยืนยัน "นกขมิ้นมีผิวหนัง" (ต้องไต่ไปถึง animal) ช้ากว่า "นกขมิ้นร้องเพลงได้" (เก็บไว้ที่ canary เอง) ผลนี้สนับสนุนว่าความจำของคนอาจจัดเก็บแบบลำดับชั้นจริง (แม้งานวิจัยรุ่นหลังจะพบข้อยกเว้นหลายอย่าง)

<Callout>
**ข้อยกเว้น (exception):** `ostrich` เก็บ `can_fly = no` ไว้ที่ตัวเอง ค่านี้ **ทับ (override)** ค่า `can_fly = yes` ที่จะได้จาก `bird` เพราะการค้นหาหยุดที่ node ที่ใกล้ที่สุดที่มีค่านั้น
</Callout>

## 3. Frames

**Frame** (Minsky, 1974) คือ "ระเบียน" ของแนวคิดหนึ่ง ประกอบด้วย **slot** (ช่องข้อมูล) และค่าในแต่ละ slot frame เชื่อมกันด้วย isA เหมือน semantic network จึงได้ inheritance เช่นกัน แต่จุดเด่นคือมองความรู้เป็น **โครงสร้างของวัตถุ** — คล้ายคลาสและอ็อบเจกต์ใน OOP ที่ตามมาทีหลัง

ข้อมูลชุดเดียวกับด้านบน แต่มองเป็น frame: ลองเลือก `ostrich` หรือ `tweety`

<FramesWidget />

ค่าใน frame มักเป็น **ค่าเริ่มต้น (default)** ที่ถูกทับได้ — "นกโดยทั่วไปบินได้" ไม่ได้แปลว่า "นกทุกตัวบินได้" นี่คือ *default reasoning* ที่ตรรกศาสตร์แบบดั้งเดิมทำได้ยาก ในระบบจริง slot ยังแนบ **procedure** ได้ด้วย เช่น *if-needed* (คำนวณค่าเมื่อมีคนถาม) และ *if-added* (ทำงานเมื่อมีการใส่ค่า)

## เปรียบเทียบ

| | Production rules | Semantic network | Frames |
|---|---|---|---|
| หน่วยความรู้ | กฎ IF–THEN | node + เส้นความสัมพันธ์ | frame + slot |
| เด่นเรื่อง | การตัดสินใจทีละขั้น | ความสัมพันธ์ระหว่างแนวคิด | โครงสร้างของวัตถุ, ค่าเริ่มต้น |
| Inheritance | ไม่มีในตัว | มี (isA) | มี (isA) + override |
| อธิบายเหตุผล | ง่าย (ย้อนดูกฎ) | ดูเส้นทางในกราฟ | ดูว่าค่ามาจาก frame ไหน |

ระบบจริงมักใช้ **ผสมกัน** เช่น frame เก็บโครงสร้างของวัตถุ และกฎใช้ตัดสินใจโดยอ่านค่าจาก slot
