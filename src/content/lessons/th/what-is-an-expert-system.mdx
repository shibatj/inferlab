# Expert System คืออะไร

**Expert system** คือโปรแกรมที่ใช้ **ความรู้เฉพาะทาง** ของผู้เชี่ยวชาญ ร่วมกับ **กลไกการอนุมาน** เพื่อแก้ปัญหาที่ปกติต้องอาศัยความเชี่ยวชาญของมนุษย์ เช่น วินิจฉัยโรค หาสาเหตุที่เครื่องจักรเสีย หรือจัดสเปกคอมพิวเตอร์ให้ตรงกับคำสั่งซื้อ

Edward Feigenbaum ผู้บุกเบิกสาขานี้สรุปไว้ว่า พลังของระบบแบบนี้มาจาก **ความรู้** ที่มันมี มากกว่าความฉลาดของอัลกอริทึมที่ใช้ — แนวคิดที่เรียกกันว่า *"knowledge is power"*

## ส่วนประกอบหลัก

| ส่วนประกอบ | หน้าที่ | ใน InferLab |
|---|---|---|
| **Knowledge base** | เก็บความรู้ระยะยาวของโดเมน ส่วนใหญ่อยู่ในรูปกฎ IF–THEN | กฎ `rule` ใน editor |
| **Working memory** | เก็บข้อเท็จจริงของ *กรณีปัจจุบัน* ที่กำลังพิจารณา | `fact` และข้อสรุปที่ได้ระหว่างทาง |
| **Inference engine** | เลือกว่าจะใช้กฎไหนกับข้อเท็จจริงไหน แล้วสรุปผลใหม่ | forward / backward chaining |
| **Explanation facility** | ตอบว่า *ได้ข้อสรุปมาอย่างไร* (HOW) และ *ทำไมต้องถามเรื่องนี้* (WHY) | แผง HOW / WHY |
| **User interface** | รับข้อมูลจากผู้ใช้และแสดงผล | หน้า Playground |

<Callout>
หัวใจของ expert system คือการ **แยกความรู้ (knowledge base) ออกจากกลไกการใช้ความรู้ (inference engine)** เราเพิ่มหรือแก้กฎได้โดยไม่ต้องแตะ engine เลย — และ engine ตัวเดียวกันใช้กับความรู้ต่างโดเมนได้
</Callout>

## ต่างจากโปรแกรมทั่วไปอย่างไร

ในโปรแกรมทั่วไป ความรู้กับลำดับการทำงานปนกันอยู่ในโค้ด:

```
if (lightsDim && clickingSound) return "battery dead";
else if (noLights) return "battery dead";
...
```

ถ้าผู้เชี่ยวชาญบอกกฎใหม่ เราต้องหาว่าจะแทรกตรงไหน และระวังไม่ให้ลำดับ if-else เดิมพัง ส่วนใน expert system เราแค่เพิ่มบรรทัด

```
rule C6: IF engine_cranks AND smell_fuel THEN engine_flooded
```

แล้ว inference engine จะตัดสินเองว่าเมื่อไหร่ควรใช้กฎนี้ แนวคิดนี้ทำให้เกิด **expert system shell** เช่น EMYCIN (คือ MYCIN ที่ถอดความรู้ทางการแพทย์ออก เหลือแต่ engine) และ CLIPS ของ NASA ซึ่งยังใช้งานกันอยู่

## เมื่อไหร่ควรใช้ expert system

เหมาะเมื่อ:

- **โดเมนแคบและชัดเจน** เช่น "วินิจฉัยปัญหารถสตาร์ทไม่ติด" ไม่ใช่ "ซ่อมรถทุกอย่าง"
- **มีผู้เชี่ยวชาญจริง** ที่อธิบายเหตุผลของตัวเองเป็นกฎได้ และยินดีถ่ายทอด
- **ต้องการคำอธิบาย** ว่าทำไมได้ผลนี้ เช่น งานที่ต้องตรวจสอบย้อนหลังได้
- **ไม่มีอัลกอริทึมตรง ๆ** ที่แก้ได้ง่ายกว่า

ไม่เหมาะเมื่อปัญหาต้องใช้ **สามัญสำนึก (common sense)** กว้าง ๆ หรือความรู้เปลี่ยนเร็วจนดูแลกฎไม่ไหว — เราจะกลับมาคุยเรื่องข้อจำกัดเหล่านี้ในบทที่ 6
