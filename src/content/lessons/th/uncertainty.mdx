# ความไม่แน่นอน (Reasoning under Uncertainty)

ผู้เชี่ยวชาญจริงแทบไม่เคยพูดว่า "แน่นอน 100%" — หมอพูดว่า "*น่าจะ*เป็นเชื้อตัวนี้" ช่างพูดว่า "*ส่วนใหญ่*เป็นที่แบตเตอรี่" บทนี้ดูสามวิธีที่ expert system ใช้จัดการความไม่แน่นอน

## 1. Certainty Factors (MYCIN)

ทีม MYCIN ที่ Stanford ต้องการวิธีที่แพทย์ให้ตัวเลขได้ง่าย จึงคิด **certainty factor (CF)** — ตัวเลขใน **[−1, 1]**: 1 = เชื่อว่าจริงแน่นอน, −1 = เชื่อว่าเท็จแน่นอน, 0 = ไม่มีหลักฐาน

สี่สูตรที่ต้องรู้ (ทั้งหมดอยู่ใน engine ของ InferLab):

| เรื่อง | สูตร |
|---|---|
| เงื่อนไข AND | CF = min(CF ของแต่ละเงื่อนไข) |
| กฎ fire | CF ข้อสรุป = CF เงื่อนไข × CF ของกฎ |
| Threshold | เงื่อนไขถือว่าจริงเมื่อ CF **มากกว่า 0.2** |
| หลายกฎสรุปเรื่องเดียวกัน (ทั้งคู่บวก) | CF = a + b × (1 − a) |

**ตัวอย่าง:** `fact gram_negative CF 0.9`, `fact rod_shaped CF 0.8`, `fact grows_in_blood CF 0.7` และกฎ `M2: IF gram_negative AND rod_shaped AND grows_in_blood THEN pseudomonas CF 0.4`

1. เงื่อนไข: min(0.9, 0.8, 0.7) = **0.7** → เกิน 0.2 กฎ fire ได้
2. ข้อสรุป: 0.7 × 0.4 = **0.28**
3. กฎ M3 ให้หลักฐานอีก 0.15 → รวม: 0.28 + 0.15 × (1 − 0.28) = **0.388**

<Callout tone="warn">
CF **ไม่ใช่ความน่าจะเป็น** — งานวิเคราะห์ภายหลัง (เช่น Heckerman, 1986) แสดงว่าสูตรรวม CF สอดคล้องกับทฤษฎีความน่าจะเป็นได้เฉพาะภายใต้สมมติฐานความเป็นอิสระที่แรงมาก แต่ในทางปฏิบัติ CF ใช้ง่ายและให้ผลที่ผู้เชี่ยวชาญยอมรับได้
</Callout>

## 2. Bayes' Rule

ถ้ามีข้อมูลความน่าจะเป็นจริง วิธีที่มีรากฐานทางคณิตศาสตร์คือ **Bayes' rule**:

```
P(H | E) = P(E | H) × P(H) / P(E)
```

อ่านว่า: ความน่าจะเป็นของสมมติฐาน H **หลังจาก**เห็นหลักฐาน E

**ตัวอย่างคลาสสิก:** โรคหนึ่งพบใน 1% ของประชากร ชุดตรวจให้ผลบวก 90% เมื่อเป็นโรคจริง (sensitivity) และให้ผลบวกลวง 5% ในคนที่ไม่เป็นโรค ถ้าผลตรวจเป็นบวก โอกาสที่เป็นโรคจริงคือเท่าไหร่?

ให้ D แทน "เป็นโรค":

```
P(+)     = 0.9 × 0.01 + 0.05 × 0.99 = 0.009 + 0.0495 = 0.0585
P(D | +) = 0.009 / 0.0585 ≈ 0.154
```

แค่ **ประมาณ 15%** ทั้งที่ชุดตรวจ "แม่น 90%" — เพราะโรคพบน้อย ผลบวกลวงจากคนปกติจำนวนมากจึงมากกว่าผลบวกจริง นี่คือ **base rate fallacy** ที่คนมักพลาด

ข้อจำกัดของ Bayes ใน expert system ยุคแรก: ต้องรู้ **prior** และ **conditional probability** จำนวนมาก ซึ่งผู้เชี่ยวชาญมักให้ไม่ได้ — นี่คือเหตุผลหนึ่งที่ MYCIN เลือก CF ต่อมา **Bayesian network** ช่วยลดจำนวนตัวเลขที่ต้องรู้ด้วยการระบุว่าตัวแปรไหนขึ้นต่อกัน

## 3. Fuzzy Logic

CF และ Bayes จัดการกับคำถามว่า "**จริงหรือไม่**" (uncertainty) แต่บางครั้งปัญหาคือ "**จริงแค่ไหน**" (vagueness) — 37.8 °C "มีไข้" ไหม? คำตอบไม่ใช่ใช่หรือไม่ใช่ แต่ "มีไข้ระดับหนึ่ง"

**Fuzzy logic** (Zadeh, 1965) ให้สมาชิกภาพของเซตเป็น **ระดับ** ใน [0, 1] แทนที่จะเป็น 0 หรือ 1 การอนุมานแบบ **Mamdani** มีสี่ขั้น:

1. **Fuzzify** — แปลงค่าอินพุตเป็นระดับสมาชิกของแต่ละเซต
2. **Rule evaluation** — แต่ละกฎ fire ด้วยระดับเท่ากับระดับสมาชิกของเงื่อนไข (AND ใช้ min)
3. **Aggregation** — ตัด (clip) เซตเอาต์พุตของแต่ละกฎที่ระดับนั้น แล้วรวมด้วย max
4. **Defuzzify** — แปลงรูปร่างที่ได้กลับเป็นตัวเลขเดียว เช่น จุดศูนย์ถ่วง (centroid)
